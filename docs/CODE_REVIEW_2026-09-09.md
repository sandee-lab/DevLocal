# 전체 코드 리뷰 및 정리 결과

검토일: 2026-09-09

후속 검증: 같은 날 Grok 실제 호출 9회로 한국어 50행과 네 언어 번역 40건을 검증했다. 기능 검사 18개를 통과했으며 AI 품질 경고 2건은 남았다. 상세 내용은 `docs/LIVE_REVIEW_VALIDATION_2026-09-09.md`를 참고한다. 아래 mock 검증 결과는 최초 코드 리뷰 시점의 기록이다.

FastAPI API·세션·SSE, LangGraph 노드, 시트 입출력, 한국어 교정·번역 검수, React 화면·상태·훅, 설정 저장, Streamlit 진입점 및 배포 스크립트를 검토했다. 데이터 손상이나 승인 무시에 연결되는 문제를 먼저 재현한 뒤 수정했다. 실서비스 배포 상태나 실제 LLM의 번역 품질을 검증한 결과는 아니다.

## 수정 전 점검

- [x] 사용자 기존 변경과 별도 진행 중인 변경을 확인하고 보존했다.
- [x] 레거시와 운영 경로의 참조를 확인했다. Streamlit과 `utils/ui_components.py`는 실제 실행 경로가 있어 유지했다.
- [x] 최초 회귀 테스트 12개가 수정 전 모두 실패하는 것을 확인했다.
- [x] 기존 프론트엔드 빌드는 통과했고 ESLint 경고 5건을 확인했다. 초기 빌드 실패는 샌드박스 폴더 접근 제한이었으며 허용된 실행에서 구분했다.

## 정리한 코드

- FastAPI·Streamlit·Glossary의 중복 설정 로더를 `config/app_config.py`로 통합했다.
- 서로 다른 한국어 결과 매핑을 `utils/rows.py`로 통합했다.
- 시트 자동 연결과 수동 연결의 중복 코드를 통합했다.
- 읽는 곳이 없는 그래프의 리포트 경로·대기 플래그·청크 진행 상태와 프론트엔드의 `rowLimit`, `reviewPage`, `previousStep`, 미사용 SSE 타입을 제거했다.
- 단일 스레드에서 결과를 병합하는 부분의 불필요한 Lock을 제거했다. 실제 세션 공유 상태의 Lock은 유지·보강했다.
- Writer의 중복 성공·실패 상태 기록을 한 경로로 줄였다.
- 한국어 태그 검증은 기존 공통 `validate_tags()`를 사용한다.
- Dockerfile에서 설치 대상이 없는 apt 실행 단계를 제거했다.
- FastAPI의 deprecated startup 데코레이터를 lifespan으로 변경했다.
- 테스트·문서·Dockerfile을 제외한 운영 소스는 공통 모듈 신규 추가를 포함해 약 100줄 순감소했다. 줄 수보다 데이터 정확성과 실패 복구를 우선했다.

`backup_data`는 레거시의 상태 복원에서 사용하므로 유지했다. 빈 `__init__.py`나 독립 실행 스크립트도 단순히 참조 횟수가 적다는 이유로 제거하지 않았다.

## 추가 설계가 필요한 사항

### P1 — 서버 여러 대에서 세션과 설정을 공유하지 않음

후속 진행: PostgreSQL 공유 세션·작업 큐·체크포인트·설정을 구현하고 실제 DB에서 복구를 검증했다. 운영 저장소 준비와 배포는 남아 있다. [구현·운영 적용 안내](P1_OPERATIONS.md)를 참고한다. 아래는 최초 리뷰 당시의 근거다.

근거: `backend/api/session_manager.py`는 프로세스 메모리에 세션을 보관하고, 설정은 `.app_config.json`에 저장한다. 반면 `deploy.sh`는 최대 인스턴스 5개를 허용한다. 요청이 다른 인스턴스로 가거나 인스턴스가 재시작되면 세션 복구를 보장할 수 없다. 이번의 프로세스 내부 Lock은 이 문제를 해결하지 않는다.

운영 확장 전 세션·체크포인트·설정의 공용 저장소가 필요하다. 단일 인스턴스로 제한하는 것은 임시 대응이며 재시작 시 유실까지 해결하지 못한다. 저장소 도입과 배포 구성 변경은 이번 코드 정리에 포함하지 않았다.

### P1 — 공개 배포와 사용자 인증

후속 진행: Google IAP 서명 검증, 관리자 설정 권한, 인증 필수 배포 구성을 구현했다. 실제 팀 IAP 접근 정책과 운영 배포는 적용 전이다. [구현·운영 적용 안내](P1_OPERATIONS.md)를 참고한다. 아래는 최초 리뷰 당시의 근거다.

근거: `deploy.sh`에 `--allow-unauthenticated`가 있고 앱 API에 사용자 인증이 없다. 별도 접근 제어가 없다면 URL을 아는 사람이 설정 변경·번역 실행 API를 호출할 수 있다. 현재 운영 환경에 외부 인증 계층이 있는지는 확인하지 않았다.

팀 전용 인증 또는 배포 플랫폼 접근 제어와 사용자별 권한 범위를 결정해야 한다. 임의의 인증 방식을 새로 도입하거나 현재 배포 권한을 변경하지 않았다.

### P2 — 실패한 LLM 호출 비용의 집계

근거: `utils/llm.py`는 JSON 파싱 성공 이후 usage를 반환한다. 파싱 실패 후 청크 분할이 성공해도 실패했던 부모 호출의 토큰은 집계에서 빠질 수 있다. 따라서 현재 비용 표시는 과금 명세와 항상 같다고 볼 수 없다.

개선 방향은 파싱 여부와 무관한 호출 단위 usage 계측이다. 부분 성공·재귀 분할·취소까지 포함하는 집계 방식을 별도로 정해야 한다. 모델·단가·reasoning 설정은 변경하지 않았다.

### P2 — Glossary 미준수 처리 강도

근거: `apply_glossary_postprocess()`는 남아 있는 한국어 용어와 정의된 오표기를 치환하지만, `check_glossary_compliance()`의 위반은 현재 경고로 처리한다. 다른 일본어 표현으로 의역된 등급명을 항상 강제 복원하는 구조는 아니다.

등급명처럼 반드시 차단해야 하는 용어와 일반 권장 용어를 구분해야 한다. 단순 부분 문자열 탐지 결과를 전부 실패로 바꾸면 일반 문장의 오탐·재시도가 증가할 수 있어, 이번에는 강제 적용 범위를 임의로 확대하지 않았다.

## 검증 결과와 한계

- Python 회귀·LangGraph 통합 테스트 26건 통과.
- 프론트엔드 SSE·시트 큐 회귀 검증 7건 통과.
- 기존 `scripts/verify_mock_only.py`의 분할 재시도·응답 완전성 검사 통과.
- `npm run build` 통과: TypeScript 검사 및 프로덕션 번들 생성.
- `npm run lint` 통과: 기존 경고 5건 해소.
- Python 소스 36개 구문 검사 및 `git diff --check` 통과.

테스트는 LLM·Google Sheets·실제 백업 저장을 mock으로 대체했다. 실제 시트 변경, 유료 LLM 호출, 배포, 커밋·푸시는 수행하지 않았다. 프론트엔드 회귀 검증은 훅의 모의 실행이며 실제 브라우저의 전체 화면 E2E 검증은 아니다.

한국어 검수 프롬프트는 응답 완전성 검사와 일치하도록 변경 없는 행도 입력 순서대로 반환하게 수정했다. 실제 모델의 응답 품질·비용 변화는 별도 실측이 필요하다. 취소 전에 이미 발송한 LLM 요청의 서버 처리나 과금은 소급 취소할 수 없으며, 이번 변경은 대기 청크와 이후 상태 반영을 차단한다.
